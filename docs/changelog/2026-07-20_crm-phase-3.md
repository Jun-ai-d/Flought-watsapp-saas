## CRM & Workflow Automation (Phase 3)

**Date:** 2026-07-20
**Project:** Flought SaaS
**Branch:** main  |  **Commit:** uncommitted
**Type:** Feature

### Issue
- Symptom: Flought's bot engine was rigid, lacking visual flow builders, CRM integrations, and basic productivity tools (SLA tracking, internal notes) for human agents.
- Root cause: Missing underlying graph execution engine, schema for CRM credentials, and background timers for SLA evaluation.
- How the root cause was confirmed: Identified during competitor research phase ("20 missing features").

### Fix
- Implemented `bot_flow_graphs` table to store JSON AST representations of visual drag-and-drop workflows.
- Built `flowEngine.ts`, an in-memory graph evaluator that traverses nodes (`trigger`, `condition`, `action`, `handoff`) and dynamically routes user context.
- Implemented `crm_credentials` table and `crm.ts` route to securely store encrypted OAuth tokens for HubSpot/Salesforce.
- Built `hubspotSync.ts` stub to push contact data to external CRMs.
- Implemented `conversation_notes` table and `notes.ts` route to enable internal, hidden chatter among human agents (F16).
- Built `slaWorker.ts` with `pg-boss` to monitor conversation resolution times. If a conversation is unresolved for >15 minutes, it automatically flags the breach via an internal note (F15).

### Blast Radius
- The `flowEngine` evaluates recursively; a hard limit of 50 iterations was added to prevent Node.js thread blocking from cyclic workflows.
- Agent notes add a new dimension to API security; RLS ensures agents can only read notes for their tenant.

### Follow-up / Known Debt
- Native CRM Integrations (F12) are partially stubbed; they require full OAuth2 callback loops and webhook syncs.
- The Visual Flow Builder (F11) requires the Phase 4 Frontend Developer to actually build the React Flow canvas to generate the AST this engine executes.
